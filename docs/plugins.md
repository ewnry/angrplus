# Плагины Antigravity+ — экспериментальное API 2.1.19

Папка плагинов: `~/.gemini/antigravity/plugins/`. Каждый плагин — отдельная папка с `plus-plugin.json`. Для пробы скопируйте `examples/plugins/hello` в эту папку, замените `"enabled": false` на `true` и перезапустите Antigravity. На экране появится небольшая надпись. Удалите папку или установите `enabled: false` и перезапустите приложение, чтобы отключить её.

```json
{
  "id": "my-plugin",
  "name": "My plugin",
  "version": "1.0.0",
  "enabled": true,
  "main": "main.cjs",
  "renderer": "renderer.js",
  "css": "style.css",
  "patch": "patch.cjs"
}
```

Все поля с файлами необязательны; пути должны указывать внутрь папки плагина. Плагин запускается только при `enabled: true`. После изменения манифеста перезапустите приложение. Файлы плагинов исполняются с правами пользователя: включайте только те, которым доверяете. Это не песочница браузерных расширений.

## Основной процесс

`main.cjs` — обычный CommonJS-модуль Node.js. `activate(api)` вызывается при старте. Можно вернуть функцию для очистки при выходе. Исключение одного плагина записывается в журнал и не препятствует загрузке остальных.

```js
exports.activate = (api) => {
  api.log('Language server port:', api.getLanguageServerPort());
  const { app, BrowserWindow, electron } = api;
  // Полный доступ к Node.js и Electron: меню, окна, процессы, IPC и т.д.
  return () => {};
};
```

`getLanguageServerPort()` возвращает текущий порт или 0, пока сервер ещё не готов. Сам протокол language server не является стабильным публичным API; его команды и авторизация зависят от версии Antigravity. Порт сам по себе не выдаёт авторизацию или готовый API для всех команд.

## Интерфейс

`renderer.js` выполняется в контексте страницы локального окна Antigravity после `dom-ready`; здесь доступны DOM и `window`. Код исполняется повторно при навигации, поэтому делайте изменения идемпотентными. `css` подключается к тому же окну. Для действий с Node.js используйте `main.cjs`, а не предполагайте доступ к Node в интерфейсе.

## Изменение app.asar

`patch.cjs` запускается при применении патча, перед упаковкой подготовленной копии архива. Полученный `root` — распакованная временная копия, `fs` и `path` — стандартные модули Node.js. Исключение прерывает установку до замены рабочего архива.

```js
exports.patch = async ({ root, fs, path, log }) => {
  const file = path.join(root, 'assets', 'my-plugin.txt');
  fs.mkdirSync(path.dirname(file), { recursive: true });
  fs.writeFileSync(file, 'hello');
  log('Added asset');
};
```

Включение, изменение или удаление `patch` требует повторного применения патча с закрытым Antigravity. При следующем применении архив заново собирается из проверенной исходной версии, поэтому неактивные изменения не сохраняются. Проверки целостности патчера могут отклонить изменение его обязательных точек интеграции или распакованных файлов. Совместимость с будущими версиями приложения не гарантируется.

Прямой Python SDK и MCP для создания плагинов ещё не реализованы. Управление файловыми плагинами находится в General+. Из JavaScript-плагина можно запускать внешние процессы стандартными средствами Node.js, но готового Python-протокола пока нет.

## Готовый API для панели и данных

Не обязательно искать DOM-элемент, создавать панель и управлять таймерами. Достаточно описать данные и место показа в `main.cjs`:

```js
exports.activate = (api) => {
  api.ui.panel({
    id: 'server-status',
    title: 'Language server',
    position: 'bottom-right',
    refreshMs: 5000,
    read: () => {
      const server = api.data.languageServer();
      return server.ready ? `Работает: ${server.port}` : 'Запускается…';
    },
  });
};
```

Патч сам создаст панель в окне приложения, обновит данные и удалит панель при завершении плагина. `read` может вернуть строку, объект или Promise. Объект показывается как JSON. `position`: `top-left`, `top-right`, `bottom-left`, `bottom-right`. `refreshMs` необязателен; минимальный интервал — 1000 мс. Сетевой JSON можно получить через `await api.data.json('https://example.com/data.json')`, а обработать в `read` обычным JavaScript. Ошибки записываются в журнал, при следующем обновлении чтение повторяется. `api.ui.panel(...)` возвращает функцию удаления панели.

Готовый пример расположен в `examples/plugins/server-status`. Эти функции дополняют низкоуровневый доступ: по-прежнему доступны `api.app`, `api.BrowserWindow`, `api.electron`, стандартные модули Node.js, `renderer`, CSS и `patch`. Можно смешивать готовые методы с собственным кодом или полностью использовать прямой доступ. Готовые панели пока доступны только в углах окна; произвольные вкладки и встроенные области потребуют собственного кода до появления отдельных методов.

### Внешний вид

Панели не навязывают цвета, шрифты или оформление. Укажите `className` в `api.ui.panel` и подключите свой `css` в манифесте. Плагин может использовать CSS-переменные и классы текущего Antigravity, а также писать свои правила. Параметр `position` необязателен; если его указать, низкоприоритетное правило задаёт расположение, которое можно переопределить обычным CSS. Для произвольной разметки используйте `renderer.js`: готовый API панели не ограничивает прямой доступ к DOM.
